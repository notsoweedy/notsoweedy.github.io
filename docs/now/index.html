I’m currently reading about GPU architecture: what happens inside a GPU, and how it works at a high level.

decoded: making deep learning go brrrr

My first ever blog on what happens inside a GPU was Horace He’s Making Deep Learning Go Brrrr From First Principles. Here’s what I understood from it, in my own words.

When a neural network model runs on a GPU, you can expect one of these things to be happening:

  1. compute: the compute cores in the GPU doing the actual math (adds and multiplies). The fastest of them, tensor cores, are only brilliant at matrix multiplication.
  2. memory bandwidth: there are 2 types of memory. SRAM is small and fast, and is called shared memory. DRAM is huge, and is called global memory. The time spent moving tensors (data) between DRAM and SRAM is the memory-bandwidth cost.
  3. overhead: time spent on everything else, from the Python interpreter to dispatching kernels and launching them on the GPU.

The blog is mostly about how to identify the bottleneck of the system, meaning what might be slowing it down, and how to fix it. It emphasizes one very important thing: if you speed up the wrong part, you won’t really get any faster. So it’s important to first work out who the culprit is: compute, memory bandwidth or overhead.

  • overhead: if you double the batch size (the data) and the system gets only about 10% slower, it’s mostly overhead. How do you fix it? By tracing. The blog mentions a couple of other techniques too, which I’m yet to read about.
  • compute: this one’s easy. The FLOPS achieved are close to peak (you’re maxing the GPU out) and the work is heavy on matrix multiplication. The fix is to make sure you’re using tensor cores, or to pay NVIDIA for more compute.
  • memory bandwidth: the work isn’t heavy on matrix multiplication. Instead it’s lots of pointwise and normalization ops, the FLOPS are low, and the memory is busy. People fix this with operator fusion.

I learned many new terms while reading it. For example, FLOPS (floating-point operations per second) measures the speed of a GPU chip: how many operations its compute units can do per second. NVIDIA’s A100 can do 312 trillion FLOPS on matrix multiplication.

To make sure I really got it, I rebuilt the blog as an interactive guide with sliders and small experiments for each idea (source on GitHub).
